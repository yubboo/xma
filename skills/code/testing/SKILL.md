# Code Testing

## 目标

用最小充分的验证链证明代码修改可工作，并把失败结果继续反馈给当前任务。

## 工作方法

1. 优先读取项目已有脚本和开发说明，使用项目自己的检查入口。
2. 先运行与修改最相关的测试，再根据风险决定是否扩大到 typecheck、全量测试或构建。
3. 不因为单个局部测试通过就忽略明显受影响的相邻模块。
4. 命令失败时保留关键错误信息，分析后继续修复，不重复盲跑同一命令。
5. 不通过任意 shell 绕过 XMA 的 executable allowlist、Approval 或 Native Capability。
6. 如果当前 ToolPlan 没有可用的 Process Tool，不得假装执行测试；必须明确标记为“未验证”，说明缺少的执行能力。
7. 最终记录实际执行的命令、退出状态和关键验证结论。
